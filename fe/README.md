# ReviewAnaler Chrome 확장프로그램

1. [WAS](../was/README.md)를 실행합니다. 로컬 기본 주소는 `127.0.0.1:8765`입니다.
2. Chrome에서 `chrome://extensions`를 열고 개발자 모드를 켭니다. **압축해제된 확장 프로그램을 로드합니다**를 눌러 이 `fe` 폴더를 선택합니다.
3. 쿠팡 상품 탭에서 ReviewAnaler를 열고 **리뷰 조회**를 누릅니다. 기본 요청 위치는 열린 상품 탭입니다. **확장프로그램 서비스 워커**를 선택하면 입력한 상품 ID로 확장에서 직접 요청합니다. 기존 설치는 확장프로그램을 새로고침해 변경된 쿠팡 도메인 권한을 적용합니다.
4. **정렬**에서 쿠팡 기본순 또는 최신순을 선택합니다. **별점 필터**에서 전체·1점·2점을 선택할 수 있습니다. 기본값은 전체 별점이며 한 번에 10건을 요청합니다. **조회 페이지** 숫자를 변경해 다음 목록을 조회할 수 있습니다. 별점 필터의 페이지 수는 별점별 리뷰 집계에서 계산한 예상값입니다. 정렬이나 별점 필터를 바꾸면 조회 페이지는 1로 돌아갑니다. 각 리뷰의 **작성자의 다른 상품평** 버튼으로 해당 작성자의 공개 상품평을 15건씩 조회할 수 있습니다. 현재 상품의 평은 목록에서 제외합니다. 분석할 리뷰를 체크하고 **선택한 리뷰를 분석 목록에 추가**를 누릅니다. 여러 페이지에서 추가할 수 있으며 같은 리뷰 ID는 중복 추가하지 않습니다.
5. 분석 목록을 확인하고 **분석하기**를 누릅니다. 분석은 요청당 최대 8건, 본문은 건당 최대 3,000자입니다. 긴 리뷰는 조회 목록에 표시하되 선택을 제한합니다. 서버 포트를 바꿨다면 **로컬 WAS 설정**에도 같은 포트를 입력합니다. 팝업을 닫으면 조회 목록과 입력은 초기화됩니다.

본문 직접 입력과 **선택한 본문 가져오기**도 사용할 수 있습니다. 수집된 제목과 본문은 줄바꿈으로 연결하며, WAS에는 상품 ID, 별점, 본문과 확인 가능한 리뷰 ID·옵션 상품 ID·작성일을 보냅니다. 같은 상품에서 마지막으로 조회한 페이지의 별점과 확인 가능한 메타데이터는 별도 표본으로 전달합니다.

응답에 제목과 본문이 모두 빈 리뷰도 별점과 함께 표시하며 **응답에 본문 없음**으로 안내합니다. 이 항목은 분석 선택이 제한됩니다. 수신·표시·본문 없음·분석 선택 가능·별점 형식 오류 건수를 확인할 수 있습니다. 본문 있는 리뷰가 없으면 정렬이나 조회 페이지를 변경해 다시 조회합니다.

## 직접 요청 프로토타입의 범위

`/next-api/review`에 상품 ID, 페이지, 크기, 선택한 정렬·별점을 담아 GET 요청합니다. 쿠팡 기본순은 `ORDER_SCORE_ASC`, 최신순은 `DATE_DESC`이며, 별점은 `ratings` 쿼리로 전달합니다. 작성자 이력은 `/next-api/review/profile/reviews`에 원래 리뷰의 `reviewId`·`vendorItemId`, 0부터 시작하는 페이지 번호를 보냅니다. 이력 조회는 상품 탭에서 실행하며 상품 페이지를 이동하지 않습니다. 요청에는 `credentials: include`와 15초 타임아웃을 적용합니다. 리뷰 조회의 서비스 워커 방식에는 `https://www.coupang.com/*` 호스트 권한을 사용합니다.

임시 Chrome 검증에서는 두 리뷰 조회 방식 모두 HTTP 403이었습니다. 사용자가 직접 연 Chrome에서는 탭 방식으로 HTTP 200·10건 수신·10건 표시를 확인했고, 1점 필터로 조회한 실제 리뷰 1건을 로컬 WAS·Jev에서 분석해 결과를 화면에 표시했습니다. 서비스 워커 방식은 HTTP 403이었습니다. 사용자 Chrome 상품 페이지의 프로필 사진을 클릭하면 URL 변경 없이 작성자 이력 GET 두 건과 팝업 표시가 확인됐습니다. 확장의 **작성자의 다른 상품평** 버튼과 이전·다음 이동도 사용자 Chrome에서 정상 동작했습니다. 응답 형식이 다르거나 서버가 거부하면 화면에 오류를 표시합니다.

응답 구조 참고 자료는 [공개 파서 구현](https://github.com/Noah3521/coupang-sourcing/blob/main/src/coupang_sourcing/normalize.py), [요청 URL 구현](https://github.com/Noah3521/coupang-sourcing/blob/main/src/coupang_sourcing/urls.py)입니다. 쿠팡이 보장하는 공개 API 계약으로 확인된 자료는 아닙니다.

## 테스트

실제 쿠팡 조회는 **사용자가 직접 실행한 Chrome의 기존 세션에서 수동 테스트**하는 것을 권장합니다. 위 실행 순서에 따라 확장을 새로고침하고, 요청 위치를 **열린 쿠팡 상품 탭**으로 선택합니다. 당분간 실제 서비스 검증은 이 방식으로 진행하며, 임시 테스트 세션의 403·응답 대기 문제 조사는 보류합니다. 자세한 근거는 [테스트 기록](review.md)에 있습니다.

프로젝트 루트에서 아래 명령을 실행합니다. Chrome, Node.js, `was/.venv`가 필요합니다. 팝업 통합 테스트는 모의 Jev를 사용합니다.

```powershell
node .\fe\tests\smoke\smoke.mjs
node .\fe\tests\popup\smoke.mjs
```

팝업 테스트는 Chrome 네트워크 인터셉트로 쿠팡 응답을 제공하고, 실제 FastAPI 앱과 모의 Jev를 사용합니다. 탭·서비스 워커 GET 요청, 조회 페이지·별점 필터, 작성자의 다른 상품평 조회와 페이지 이동, 상품 탭의 선택한 본문 가져오기, 리뷰 선택과 WAS 전송, 중복·길이 제한, 빈 응답, HTTP 403, 알 수 없는 응답 구조를 검증합니다.

실제 쿠팡 요청도 함께 확인하려면 다음 명령을 실행합니다. 별도 임시 프로필의 헤드리스 Chrome을 사용합니다. 기본 주소의 WAS가 실행 중이고 Jev 키가 설정돼 있으면 가상 리뷰 한 건도 실제 분석합니다. 이 경우 AI 사용량이 발생할 수 있습니다. `LIVE` 출력은 실제 관측값이며 테스트의 `PASS`는 모의 응답 검증 결과입니다.

```powershell
node .\fe\tests\popup\smoke.mjs --live
```

실제 Jev 호출을 생략하고 현재 확장의 쿠팡 조회와 팝업 표시 결과를 재검증하려면 아래 명령을 사용합니다. `--headed`는 창이 있는 Chrome으로 실행합니다. 각 실행은 새 임시 프로필을 사용하며, 실제 응답 상태·제한된 응답 헤더·리뷰 표시 건수를 출력합니다.

```powershell
node .\fe\tests\popup\smoke.mjs --coupang-live
node .\fe\tests\popup\smoke.mjs --coupang-live --headed
```

쿠팡 상세 페이지와 상품평 요청의 상태 코드를 확인하려면 아래 진단을 실행합니다. 별도의 일반 Chrome 프로필이 열립니다.

```powershell
node .\fe\tests\coupang\trace.mjs
```

재현 조건, 확인 결과, 프론트엔드 구현 참고사항은 [review.md](review.md)에 누적합니다.
