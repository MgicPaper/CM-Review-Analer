## 쿠팡 리뷰 조회

수동 검증 기준은 사용자가 직접 실행한 Chrome의 기존 세션. 확장 새로고침 → 상품 탭 열기 → **열린 쿠팡 상품 탭 / 쿠팡 기본순 / 1페이지**로 조회.

| 환경 | 요청 | 결과 |
| --- | --- | --- |
| 사용자 Chrome, 수정본 | 확장 상품 탭 | HTTP 200. 1/249페이지. 수신 10건, 표시 10건, 분석 선택 가능 10건. 본문 없음·별점 형식 오류 각 0건 |
| 사용자 Chrome, 1점 필터 | 확장 상품 탭 → 로컬 WAS · Jev | 쿠팡 조회 HTTP 200. 당시 화면에는 1/249페이지로 표시, 수신·표시 각 10건, 본문 없음 1건, 분석 선택 가능 9건. 선택한 저별점 리뷰 1건 분석 완료, 화면에 `상품 자체`·상품 단점 언급 확률 92% 표시. 사용자가 결과를 보고함 |
| 사용자 Chrome, 앞선 검증 | 확장 서비스 워커 | HTTP 403 |
| 임시 Chrome, 헤드리스 | 상품 상세, 확장 탭·서비스 워커 | 모두 HTTP 403(`AkamaiGHost`). 팝업 표시 0건 |
| 임시 Chrome, 창 모드 | 상품 상세, 쿠팡 자체 리뷰 XHR | 상세 HTTP 200(`envoy`), 리뷰 XHR HTTP 403(`AkamaiGHost`) |
| 임시 Chrome, 창 모드 | 확장 탭·서비스 워커 | 탭 조회 대기 시간 초과. 서비스 워커 후속 조회 미검증 |
| 임시 Chrome, 확장 미설치 | 쿠팡 자체 리뷰·배치 XHR | HTTP 403(`AkamaiGHost`) |
| Node.js | 상품 상세·리뷰 GET | HTTP 403, `Access Denied` |

- 임시 Chrome 조건은 `157.0.8103.51`, 실행마다 새 프로필, 상품 `7330106093`. 최신 확장 재검증은 기본순 1페이지·10건.
- 403 응답 헤더와 차단 본문상 Akamai 접근 차단 추정. 적용 규칙과 환경 차이의 원인은 미확정. 임시 세션의 403·대기 문제 조사는 보류. [네트워크 진단 스크립트](tests/coupang/trace.mjs)
- 실제 요청 결과는 `LIVE Coupang popup`·`LIVE Network` 출력에서 확인. `PASS`는 모의 검증 결과.
- 사용자 Chrome 상품 탭에서 동일한 상품 `7330106093`의 `/next-api/review`를 직접 조회한 결과, 전체 별점 기본순 1페이지는 HTTP 200·10건 모두 5점이었다. `ratings=1`은 HTTP 200·10건 모두 1점(본문 9건), `ratings=2`는 HTTP 200·10건 모두 2점(본문 3건)이었다. 이에 따라 확장 팝업에 1·2점 필터를 추가했다. 갱신한 팝업의 실제 저별점 리뷰 1건은 사용자 수동 검증으로 WAS 분석 및 결과 표시까지 확인했다.
- 필터 요청에서도 `paging.totalPage=249`와 `totalCount=2482`가 전체 별점 값으로 유지됐다. 1점 집계는 50건, 2점 집계는 46건이며 각 필터의 6페이지는 빈 목록이었다. 팝업은 별점 필터 선택 시 집계에서 계산한 예상 페이지 수를 표시한다.
- 현재 상품 페이지의 작성자 이름은 링크나 버튼이 아니지만 **프로필 사진**은 클릭할 수 있다. 사진 클릭 시 주소는 그대로이고 `/next-api/review/profile?reviewId=…&vendorItemId=…`와 `/next-api/review/profile/reviews?reviewId=…&vendorItemId=…&page=0&size=15` GET이 각각 HTTP 200이었다. 두 번째 응답의 `profilesReviews.content`에 다른 상품 리뷰, `metadata`에 페이지 정보가 있다. 다음 페이지는 `page=1`로 조회된다. 확장은 이 두 번째 GET을 상품 탭에서 요청한다. 표시 이름만으로 서로 다른 리뷰를 같은 작성자로 연결하지 않는다.
- 실제 1점 리뷰 목록의 첫 리뷰에 `reviewId`와 `vendorItemId`가 있었고, 두 값을 사용한 작성자 이력 GET도 HTTP 200·15건 수신·15건 모두 다른 상품 리뷰로 확인됐다.
- 확장 새로고침 후 사용자 Chrome에서 **작성자의 다른 상품평** 버튼과 이전·다음 이동이 모두 정상 동작했다고 사용자가 보고했다.

## 빈 본문과 응답 진단

| 관측·조건 | 처리 |
| --- | --- |
| 실제 응답 첫 리뷰의 `rating`·`reviewId`는 숫자, `title`·`content`는 빈 문자열 | 유효한 별점이면 목록에 표시, **응답에 본문 없음 · 분석 선택 불가** 안내 |
| 빈 본문·별점 오류·응답 형식 오류 | 응답 구조 진단에 필드명·자료형·길이 표시. 최대 4단계·객체당 40개 필드 |

## 통합 검증

| 검증 | 결과 |
| --- | --- |
| Chrome 팝업 · 모의 쿠팡 응답 · 실제 FastAPI · 모의 Jev | 헤드리스·창 모드 통과. 리뷰 GET 경로, 작성자의 다른 상품평 GET·페이지 이동·현재 상품 제외, 정렬·별점 변경, 별점별 예상 페이지 수, 상품 탭에서 선택한 본문 가져오기, 빈 본문 표시, 선택·중복·길이 제한, 403·스키마 오류, 분석 전송·결과 표시·호출 생략·연결 오류 확인. [팝업 테스트](tests/popup/smoke.mjs) |
| Chrome 팝업 · 실제 WAS와 Jev | 가상 2점 리뷰 분석 HTTP 200. 로컬 연결 오류의 재현 조건과 토큰 수는 [WAS 검증 기록](../was/review.md) 참조 |
| 샘플 HTML · FastAPI 테스트 서버 | 샘플 리뷰 2건(저별점 1건) 전송 HTTP 200. 프로필 열기 전후 이력 0→2건. [샘플 전송 테스트](tests/smoke/smoke.mjs) |

최근 팝업 통합 테스트는 첫 실행에서 모의 상품 탭의 직접 리뷰 수집 대기 시간이 초과됐고, 재실행은 전체 통과했다. 임시 Chrome과 네트워크 가로채기 단계의 간헐적 대기 문제는 남아 있다.

## 남은 검증

- 사용자 Chrome의 실제 쿠팡 리뷰 본문에서 **선택한 본문 가져오기** 수동 확인. 모의 상품 탭을 이용한 자동 검증은 통과
- 사용자 Chrome에서 현재 상품의 평 제외와 다른 상품평의 본문·별점·작성일 표시 개별 확인
- 작성자 공개 이력을 이용한 작성 빈도·별점 분포 계산과 WAS 분석 연결
