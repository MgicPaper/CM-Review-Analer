# WAS 구현 및 문제 기록

기준일 2026-11-12. [실행·설정](README.md) · [API와 분석 범위](../wiki.md#현재-api) · [Chrome·쿠팡 검증](../fe/review.md)

## 검증 결과

- Jev 모의 테스트 통과. 설정 우선순위·포트 검증, 1~2점 배치·토큰 처리, 3~5점만 있을 때 호출 생략, 키 누락, 제공자 오류·불완전 응답·잘못된 입력 확인. [Jev 모의 테스트](tests/verify_jev.py)
- 실제 Jev 호출 2건 모두 가상 2점 리뷰, HTTP 200, `jev-1.14.0`, 불만 범위 `product`.

| 요청 경로 | 단점 언급 확률 | 입력 토큰 | 출력 토큰 |
| --- | --- | --- | --- |
| WAS 직접 요청 | 0.96 | 556 | 79 |
| Chrome 서비스 워커 | 0.95 | 542 | 79 |

## 환경 문제

| 증상 | 원인·조치 |
| --- | --- |
| `uv sync` 후 `was/.venv` 미생성 | 상위 Desktop uv 워크스페이스의 공유 가상환경 사용. 분리 후 `was/.venv`의 Python 3.14.7과 의존성 로딩 확인 |
| 로컬 WAS 연결 `connect EACCES` | Codex Windows 격리에서 실제 WAS와 테스트 프로세스 자체의 리스너 모두 TCP 연결 거부. 격리 밖에서 두 연결 성공. 실제 WAS의 `GET /health`와 Chrome 서비스 워커 분석 요청 HTTP 200. 가상 5점 리뷰로 Jev 호출 생략 |

## WAS 오류 응답

| 상태 | 반환 조건 |
| --- | --- |
| `422` | 상품 ID, 리뷰 건수, 별점 자료형·범위 또는 본문 길이 검증 실패 |
| `502` | Jev 호출 오류 또는 불완전한 판단 응답 |
| `503` | 1~2점 리뷰 분석에 필요한 키 누락 또는 Jev 호출 한도 도달 |
| `504` | Jev SDK 타임아웃 |

## 2026-11-13 실제 리뷰 검증

- 사용자 Chrome에서 실제 쿠팡 1~2점 리뷰 한 건을 기존 `8765` WAS에 전송했습니다. 사용자가 팝업에서 `리뷰 1 · 상품 자체 · 상품 단점 언급 확률 92%`를 확인했습니다.
- 이 요청의 토큰 수는 팝업에 표시되지 않아 별도 응답 수치가 확인되지 않았습니다. 위 가상 리뷰 검증에서 실제 Jev의 토큰 반환 경로를 확인했습니다.

## 리뷰 입력 형식 확장

- 분석 요청에 선택형 리뷰 메타데이터와 본문 없는 `review_sample`을 추가했습니다. 결과에 원래 리뷰 ID가 있으면 함께 반환합니다.
- Jev에는 기존과 동일하게 1~2점 리뷰 본문만 전달합니다. 표본만 보내면 Jev를 호출하지 않습니다.
- WAS 테스트에서 기존 응답 형식, 메타데이터 표본, 날짜 검증과 리뷰 ID 연결을 확인했습니다. Chrome 통합 테스트에서는 수집 리뷰의 ID가 분석 결과까지 전달되는 것을 확인했습니다.
